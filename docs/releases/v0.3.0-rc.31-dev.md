`0.3.0-rc.31-dev` は文節境界の引き継ぎと左右キーの操作段階を修正するテスト版です。ユニバーサル debug 署名 APK（`me.zssu.ime.debug`、versionCode 55）で、正式署名版ではありません。

## rc.30-dev からの修正

- 入力中に左右キーや長押しカーソルで選んだ読みの先頭側の区切りを、最初の変換時の第一文節に引き継ぎます。後ろへの追加入力でも保持し、記録した読みの先頭部分を編集したときは古い指定を破棄します。
- 最初の変換直後は左右キーで前／次の文節へ移動。もう一度変換して候補選択に入った後は、左で文節を縮め、右で広げます。
- 候補選択中でも文節操作ボタン・文節の直接タップ・長押しカーソルでは文節移動ができます。部分確定後は次の文節の移動段階へ戻ります。
- Mozcが文節幅変更などで候補ウィンドウを隠したとき、変換終了と誤判定していた問題を修正。候補全体の変換状態とフォーカスを使用し、次の変換で境界を再計算し直すことを防ぎます。
- 文節の読みをMozcから保持し、漢字表示の長さを使わずに境界を合わせます。UnicodeのコードポイントとAndroidのUTF-16位置も区別します。
- リアルタイム解析は従来からMozcのmixed conversionで動作しています。今回も維持し、設定上も明示的に有効化します。入力末尾では読み全体、カーソル途中では先頭側の部分予測が対象です。重いAI推論を毎打鍵追加する変更ではありません。

## 検証と制約

アプリ219件・Karukan 2件の単体テスト、debug/release lint、通常APK/AAB・ABI別APKのビルド、APK内容・16 KB配置・JNI名保持を確認しています。候補ウィンドウを持たない変換出力のprotobuf、境界復元、追加入力と編集、動かなかったカーソル、Unicode、ネイティブ調整が進まない場合の停止、操作段階を回帰テストに追加しました。

実機・エミュレータでの連続入力、文節操作、入力先ごとの挙動、速度・快適性は未確認です。入力中の指定は読み先頭からの1つの区切りで、複数の固定境界を入力前に設定する機能ではありません。ネイティブ側で境界が変化しない場合は、変換し直したり無限に再試行したりせず、その状態で停止します。応答自体がない場合は古い状態を表示せず、通常のセッション復旧へ渡します。

操作と実装の詳細は[変換UI・文節操作](https://github.com/zenskypj/Komorebi-IME/blob/v0.3.0-rc.31-dev/docs/conversion-ui.md)を参照してください。
