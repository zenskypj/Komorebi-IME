# 他IME検証：説明と、実態

これは中立の比較表ではありません。各社の**説明**と、**実際に起きたこと**、そして**ポリシーが許していること**を突き合わせる検証です。あなたが毎日すべての入力を預けている道具が、何を約束し、何を実際にしたのか。表だけを信じるのは、2013年12月より前のユーザーがしていたことです。

> [!IMPORTANT]
> ここに書くのは**公開情報と各社自身の文書**に基づく事実と、そこからの分析です。特定製品の違法性を主張するものではありません。各社の仕様は変わります。判断は一次情報で行ってください。

## 結論を先に

| 論点 | 閉源の大手IME | Komorebi IME |
| --- | --- | --- |
| 入力が送られないことを**第三者が検証できるか** | できない（ソース非公開） | できる（Apache-2.0、パッチも公開） |
| 収益源 | 広告・アカウント・サービス連携 | なし（広告SDK・解析SDKなし） |
| 入力の使途 | 変換改善**以外**にも及び得る（ポリシー明記） | 端末内の変換のみ |
| 約束の根拠 | 会社の説明 | 説明＋コード |

**一言でいうと**: 閉源のIMEは「送っていない」と言えますが、**それが本当かどうかを確かめる手段があなたにはありません**。Komorebi IME は確かめる手段を渡します。これが最大の違いです。

## 1. 会社の説明は、実装の保証ではない

Simeji（バイドゥ）はこう説明していました——**ユーザーの入力を送る場合は事前に許諾を求め、許諾がなければログを取得しない**。ところが、実際は違いました。

| 説明されていたこと | 実際に起きたこと（2013年12月） |
| --- | --- |
| ログ送信は利用者の許諾制 | **ログセッションをOFFにしていても、一部データが送信されていた** |
| バグは直した | 問題は**バージョン5.6（2013年3月公開）から8か月以上**混入していた |
| 対象は限定 | 同じ会社の**PC用「Baidu IME」でも同時に**問題が指摘された |

会社の説明を信じた利用者は、8か月以上、OFFにしたつもりで送られていました。これは特殊な事件ではなく、**閉源のソフトでは「説明」と「実装」の一致を外から確認できない**という構造の問題です。今回たまたまセキュリティ企業が通信を解析して発覚しただけです。

## 2. 実際に起きたこと（時系列）

| 日付 | 出来事 |
| --- | --- |
| 2013-12-26 | セキュリティ企業ネットエージェントが、Simeji の**入力ログが無断で外部サーバーへ送信**されていると指摘 |
| 2013-12-26 | バイドゥが「**実装バグ**」と説明。v5.6（2013年3月）から混入、OFF時も一部送信されていたことを確認 |
| 2013-12-27 | v6.6.2 で修正。あわせて**クラウド変換を初期設定でOFFに変更** |

最後の一行が示唆的です。バグを直す際、**それまで初期ONだったクラウド変換を初期OFFに変えた**。つまり問題の一部は「バグ」ではなく「**初期設定の選択**」でした。安全側にしてから出していれば、そもそも起きなかった種類の事故です。

## 3. ポリシーが「許している」こと

現在の Simeji プライバシーポリシー（2023-08-25 改定）は、丁寧に読むと踏み込んだことを書いています。

| ポリシーの記載 | 意味すること |
| --- | --- |
| ログセッション統計情報（**変換前の入力・確定後の語句・確定よみ**）を取得 | 未変換の入力そのものを対象に含む。初期値はOFF |
| 検索窓の入力文字列・**確定よみ**を「**ユーザーに最適な広告を表示するため**」に利用 | 変換改善だけではない。**あなたの入力が広告に使われる** |
| データは国内サーバーだが、**グループ企業を含む外国の第三者に提供することがある** | 保存先が国内でも、行き先は国内とは限らない |
| AI機能の入力文を **OpenAI と共有** | 入力の行き先は自社サーバーだけではない |
| パスワード・クレジットカード番号は自動判別で原則取得せず、一部マスキング | 逆に言えば、**自動判別をすり抜けたものは取得対象**になり得る |

無料で、広告で運営され、その広告を最適化するためにあなたの入力を使う——**収益構造が、入力の利用を要求している**。これは個々の善意の問題ではなく、ビジネスモデルの問題です。

> [!WARNING]
> 「OFFにすれば安全」は、Simeji が自ら崩した前提です（第2節）。初期設定が安全側かどうか、OFFの場所が分かりやすいか、そして**OFFは本当にOFFか**。自分で確かめられないなら、それは安全ではなく、ただの期待です。

## 4. Gboard の構造的な問題

Gboard は Android の既定キーボードです。Google の公式ヘルプは、送るもの・送らないものを次のように書いています。

| Google が「送る」と明記 | Google が「送らない」と明記 |
| --- | --- |
| **検索**（検索結果を返すため） | 検索**以外**に入力した内容（パスワードやチャットなど） |
| **利用統計**（よく使う機能の把握と改善） | 保存した単語 |
| 音声入力の**音声**（文字起こしのため） | — |

ここで冷静に読む必要があります。**「検索」は、あなたの入力そのものです**。「送らない」の例外として検索が置かれている。つまり「入力は送らない」という言い方は、**送る範囲を自社が定義したうえで**成立している主張です。

そして構造的な問題は3点あります。

1. **OSとキーボードが同じ会社**。既定のキーボードが最初から入っており、検索・音声・統計が同じ会社に集まる。
2. **アカウントと結びつく**。検索はGoogleアカウントの履歴と結びつき得る。入力の一部が、あなたの長期的なプロファイルに接続される。
3. **ソースが非公開**。上の表が事実かどうかを、あなたは検証できない。

「利用統計」が何を含むかは、外からは分かりません。2013年の教訓は、まさにそこです——**説明は実装と一致しないことがある**。

## 5. 最大の問題は「検証できない」こと

| | 閉源IME | ソース公開IME |
| --- | --- | --- |
| 送信先を自分で確認 | できない | できる |
| 送信内容をバイナリから確認 | 実質不可能 | できる |
| 「直した」の検証 | 次のリリースを信じるだけ | 差分を見られる |
| 事故の再発防止の根拠 | 会社の約束 | コードと権限 |

誤解しないでください。Google やバイドゥが今日も嘘をついている、と言いたいのではありません。言いたいのは一つです——**閉源である以上、あなたには確かめる手段がなく、「信じる」以外の選択肢がない**。それ自体が、すべての入力を預ける道具としては構造的な弱点です。

> [!NOTE]
> よくある反論:「大手は信用できる」「審査がある」。実際に2013年の問題は、審査を通ったストア配信アプリで起きました。ストア審査は、送信内容の妥当性を保証しません。

## 6. 検証できる側に立つ: Komorebi IME の立場

Komorebi IME は、上の問題に対する**反対の設計**を選んでいます。

| 約束 | 根拠（確かめられる） |
| --- | --- |
| 入力・文脈・辞書・学習を送らない | ソース公開。権限は `INTERNET` のみ |
| 通信は明示操作のときだけ | モデル・追加辞書の取得は利用者が押したときのみ |
| 広告・解析・クラッシュSDKなし | 依存と実装を自分で確認できる |
| 保存時に暗号化 | 辞書・学習履歴・最優先候補・定型文を Keystore の鍵で暗号化 |
| 変換は端末内 | Mozc をネイティブ組み込み。オフラインで動作 |

そして、こちらも**正直に弱点を書きます**。

| 正直な制約 | 内容 |
| --- | --- |
| 開発段階 | Release Candidate。設定・内部形式が変わり得る |
| AI の対応CPU | ニューラル変換・校正は現在 `arm64-v8a` のみ |
| 実機検証 | 一部機能は実機での継続検証が必要 |
| 機能の幅 | 多言語・音声・翻訳は大手に及ばない |
| 由来 | [soichi11208/Zinna-IME](https://github.com/soichi11208/Zinna-IME) のフォーク |

大手に勝っているのは**構造**です。便利さの総量では負けます。それを承知のうえで、**入力を渡す相手を選ぶ**という判断をしてほしい。

## 7. 選び方（はっきり言う）

| あなたが本当に大事にしたいもの | 選ぶべきもの |
| --- | --- |
| 入力内容を外に出したくない | ソースが公開されたオフラインIME（Komorebi IME など） |
| 検証できないものを信じるしかない状態を避けたい | 同上 |
| 多言語・音声・翻訳・機能の網羅性 | クラウド型IME（その代価を理解したうえで） |
| とにかく既定のままでいい | Gboard（送られる範囲は公式ヘルプで確認を） |

> [!TIP]
> どのIMEを使うにせよ、**パスワード欄で学習しない設定**と、**「利用統計」系のトグル**は確認してください。Komorebi IME はパスワード欄で自動的に学習を止めます。
