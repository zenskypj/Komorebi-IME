# 他IMEとの比較（プライバシーと機能）

このページは、Komorebi IME が「どこまで端末内で完結するか」を、他社製日本語IME・キーボードの**公開情報**と並べて確認するためのものです。

> [!WARNING]
> 比較は **2026年11月時点で公開されている情報**に基づきます。各社の仕様・プライバシーポリシーは予告なく変わります。特定製品の安全性を断定するものではなく、法的助言でもありません。最新の条件は必ず各社の公式情報を確認してください。Komorebi IME はフォーク由来の Release Candidate で、機能の一部は実機検証中です。

## 1. 入力はどこへ行くか（公開情報のまとめ）

| | Komorebi IME | Gboard | Google 日本語入力 | Simeji |
| --- | --- | --- | --- | --- |
| 変換の実行場所 | 端末内（Mozc） | 端末内 + Google サービス連携 | 端末内（端末内辞書） | 端末内 + クラウド超変換 |
| 入力本文の送信 | しない | 公式ヘルプ: 「検索以外に入力した内容（パスワードや友人とのチャットなど）は送信しない」 | Google 広報（2013年）: 「入力された文字・文章・番号が送信されることはない」 | ログセッション統計情報（変換前入力・確定語句・確定よみ）を取得する設定がある（**初期状態は OFF**） |
| クラウド変換 | なし | 検索・音声など | なし（2013年時点） | あり（クラウド超変換。利用時にクエリをサーバー処理） |
| 利用統計・診断 | 送信しない | 「利用統計」を送信（機能改善のため） | PC版は「使用統計情報と障害レポート」設定（**初期状態は OFF**） | クラッシュ情報・利用状況を取得 |
| 音声・翻訳・AI | 端末内（任意DL） | 音声は Google へ送信して文字起こし | — | 音声・翻訳・AI はサーバー処理（AI は OpenAI と共有） |
| 広告 | なし（広告SDKなし） | Google の広告・プライバシーポリシーに従う | — | ポリシーに**広告のための入力利用**を明記 |
| 保存単語・辞書 | 端末内・暗号化 | 端末内（「保存した単語は送信されない」） | 端末内 | 端末内 + サーバー |
| ソース公開 | あり（Apache-2.0） | なし | なし | なし |

<small>「—」は本ページで確認できた公開情報がない項目です。断定を避けるため空欄にしています。</small>

> [!NOTE]
> 各社とも「パスワードやクレジットカード番号は取得しない」方向の対策を取っています（Google は送信しないと明記、Simeji は自動判別で原則取得しない・一部マスキングと明記）。差が出るのは主に **①入力本文そのものを送るか、②利用統計・広告目的でどこまで使うか、③ソースが公開されているか** の3点です。

## 2. Simeji（旧 Baidu IME）で起きたこと

2013年12月、**入力ログの無断送信**が問題になりました。経緯は次のとおりです。

| 日付 | 出来事 |
| --- | --- |
| 2013-12-26 | セキュリティ企業ネットエージェントが、Simeji の入力ログがユーザーに無断で外部サーバーへ送信されていると指摘 |
| 2013-12-26 | バイドゥが「実装バグ」と説明。**バージョン5.6（2013年3月公開）から混入**していたと発表。ログセッションを OFF にしていても一部データが送信されていたことを確認 |
| 2013-12-26 | 同日中に改善版を緊急リリースすると告知。Baidu IME の事前許諾画面が見つけにくい点も改善 |
| 2013-12-27 | Simeji を v6.6.2 へ更新しバグを修正。あわせて **クラウド変換を初期設定で OFF** に変更 |

- 会社側の説明では、変換精度向上のためログを活用し、送信時は事前許諾を求める方針で、カード番号・パスワード・住所・電話番号はログとして収集しない仕様とされていました。それでも「**OFF にしていたのに送信されていた**」点が問題の核心です。
- この件をきっかけに、IME は「入力のすべてを扱う」ため信頼の前提が重要だという認識が広がりました。

> [!NOTE]
> 現在の Simeji プライバシーポリシー（最終改定 2023-08-25）によれば、ログセッション統計情報の取得は初期設定で OFF、クラウド超変換や音声・翻訳・AI はサーバー処理、検索窓の入力や確定よみは広告の最適化に利用され得る、とされています。データは国内サーバーに保管しつつ、グループ企業を含む外国の第三者へ提供することがあると明記されています。**過去＝現在ではない**点に注意し、判断は現行ポリシーで行ってください。

## 3. Gboard の「入力情報」をめぐる論点

Gboard は Android の標準キーボードで、Google のサービス（検索・音声・提案）と強く連携します。Google の公式ヘルプには次のように書かれています。

| Google が明記していること | 内容 |
| --- | --- |
| Gboard が送るもの | 検索、**利用統計**（よく使われる機能の把握と改善のため）、音声入力の**音声**（文字起こしのため） |
| Gboard が送らないもの | 検索以外に入力した内容（パスワードやチャットなど）、保存した単語 |
| 保存した単語 | 端末内にのみ保存。いつでも削除できる |
| 個人化 | 「詳細設定 → 個人化」で調整・無効化できる |

批判の中心は「**入力の一部（検索）と利用統計が Google 側に渡る**」「**既定のキーボードとして常時使われる**」という構造そのもの、そして「オフライン・広告なしで完結するキーボードのほうが安心できる」という価値観の対立です。実際、プライバシー重視の解説では Gboard の設定を無効化する手順や、HeliBoard などのオフライン・オープンソース代替が案内されています。

> [!IMPORTANT]
> 「Gboard は入力した内容をすべて Google に送っている」という言い方は、Google の公式説明とは一致しません。公式には「検索以外の入力内容は送らない、保存単語も送らない」とされています。一方で「利用統計」と「音声」は送信され、検索は送信されます。**何が送られるかを正確に見る**のが要点です。

## 4. 誤解しやすい点: Android の警告はすべての IME に出る

Android では、IME を有効化するときに次の警告が表示されます。

> 「この入力方法を選択すると、すべての入力内容の収集をアプリに許可することになります。これにはパスワードやクレジットカード番号など個人情報も含まれます。」

これは **OS がすべての IME に対して必ず出す注意喚起**で、「そのアプリが実際に収集している」という意味ではありません。実際、Google 日本語入力や ATOK のように「入力文字を収集していない」と明記する IME にも、同じ警告が出ます。

つまり、警告の有無では安全性は判断できません。**判断材料は、各アプリの公開ポリシー・送信先・ソース公開の有無・実際の権限**です。

## 5. 機能で見る比較（Komorebi IME とクラウド型IME）

ここでは特定製品ではなく「一般的なクラウド型IME」と比較します。

| 観点 | Komorebi IME | 一般的なクラウド型IME |
| --- | --- | --- |
| 変換エンジン | 端末内 Mozc（オフライン） | 端末内 + クラウド併用 |
| AI 変換 | 端末内（zenzai-plus / Karukan、任意DL） | クラウド推論が一般的 |
| AI 文章校正 | 端末内（Qwen / Gemma、任意DL） | クラウドが多い |
| 通信 | 明示操作の取得時のみ | 入力・候補ごとに通信 |
| 広告 | なし | あり（無料版） |
| 解析SDK | なし | ありが多い |
| 権限 | `INTERNET` のみ | 用途に応じて多数 |
| 保存データ | Keystore で暗号化 | 実装依存（非公開） |
| 辞書の入出力 | TSV で取込・書出 | クラウド同期が多い |
| ソース | 公開（Apache-2.0） | 非公開 |
| 料金 | 無料 | 無料（広告）/ 有料 |
| できることの幅 | 日本語中心・実機検証中 | 多言語・機能豊富 |

> [!NOTE]
> Komorebi IME が優れているのは**プライバシーの構造**です。多言語対応・機能の網羅性・変換の賢さでは、大規模サービスに及ばない部分があります。何を優先するかで選ぶべき道具は変わります。

## 6. Komorebi IME の立場（まとめ）

| 約束 | 内容 |
| --- | --- |
| 変換は端末内 | Mozc をネイティブ組み込み。オフラインで動く |
| 入力を送らない | 入力・文脈・辞書・学習履歴を外部へ送信しない |
| 通信は明示的に | モデル・追加辞書の取得は、利用者が押したときだけ |
| 広告・解析なし | 広告SDK・解析SDK・クラッシュレポートSDKを組み込まない |
| 保存時に暗号化 | 辞書・学習履歴・最優先候補・定型文を Keystore の鍵で暗号化 |
| ソース公開 | Apache-2.0。挙動を自分で確認できる |

| 制約（正直なところ） | 内容 |
| --- | --- |
| 開発段階 | Release Candidate。設定・内部形式が変わる可能性がある |
| AI の対応CPU | ニューラル変換・校正は現在 `arm64-v8a` のみ |
| 実機検証 | 一部機能は実機での継続検証が必要 |
| 由来 | [soichi11208/Zinna-IME](https://github.com/soichi11208/Zinna-IME) のフォーク。フォーク元はこの版を保証しない |

## 7. 用途別の選び方

| こんな人に | 向いている選択 |
| --- | --- |
| 入力内容を出したくない | Komorebi IME（オフライン・送信なし） |
| 多言語・多機能を最優先 | クラウド型IME |
| オープンソースを確認したい | Komorebi IME などの OSS キーボード |
| 広告なし・無料で完結したい | Komorebi IME、または他のオフラインIME |
| 音声入力・翻訳をよく使う | クラウド型IME |

> [!TIP]
> どのIMEでも、**パスワード欄では学習しない**設定を確認してください。Komorebi IME はパスワード欄で自動的に学習を止めます。
