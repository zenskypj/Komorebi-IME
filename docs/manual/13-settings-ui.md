# 設定画面と Liquid Glass

設定ホームを、Liquid Glass の考え方を Android 向けに翻訳した操作体系へ変更しました。ガラス表現は装飾ではなく、**コンテンツの上に浮かぶナビゲーション層**に限定しています。

## Liquid Glass の要件

Apple が WWDC 2025 で発表した Liquid Glass は、光を曲げて集中させる「レンズ」としての素材です。単なる半透明のぼかしではありません。公式のガイダンスから、設定画面に適用した要件を整理します。

| 要件 | 設定画面での扱い |
| --- | --- |
| ガラスはナビゲーション層だけ | 上部バー、下部のクイック操作バー、タブバーに限定。設定カード・一覧・本文は不透明なコンテンツ面 |
| ガラスを重ねない | クイックバーとタブバーは別の面として分離。選択中のタブはガラスではなく単色のインジケーター |
| Regular と Clear を混ぜない | 背景が静的な設定画面では Regular 相当の半透明表現だけを使う |
| 色付けは主操作だけ | 選択中のタブ、主要な状態、アイコンにアクセント色を使い、全体を着色しない |
| 可読性 | 文字は不透明なコンテンツ面に置き、ガラス面の文字はコントラストを確保。明暗テーマと 1dp の境界線を持つ |
| アクセシビリティ | ガラス表現を減らす切り替えを上部バーに用意。48dp 以上のタップ領域、選択状態の semantics、ラベル付きアイコン |
| フローティングするタブバー | 画面下端に余白を持つカプセル型のタブバー。ナビゲーションバーのインセットを尊重 |
| モーション | タブ選択色、クイックバーの出入り、検索の展開を短いアニメーションで表現。弾みすぎない |

## Android での実装

Android には、iOS の Liquid Glass のようなシステム全体の屈折・レンズ効果を任意の Compose 画面へ適用する API はありません。API 31 以降の `RenderEffect` はレイヤーに対するぼかしで、背後のコンテンツをサンプリングするポータブルな部品ではありません。

そのため、次の組み合わせで表現しています。

- 半透明の白／チャコールの線形グラデーション
- 上端の 1dp のスペキュラーハイライトと、全体の 1dp のガラス境界線
- 柔らかい影
- 背後に置く、低彩度のアンビエント色面
- ガラス表現をオフにすると不透明なサーフェスへ切り替わるコントラストモード

コンテンツ面はガラスにせず、`GlassSettingRow` のような不透明なカードにしています。これにより「ガラスはナビゲーション層だけ」「ガラス重ね禁止」という要件を保ちます。

## 新しい操作体系

- **5つのタブ**: ホーム、入力、変換、データ、情報。設定項目をフラットに並べず、目的から絞り込む。
- **横断検索**: 上部の検索から、タイトル・説明・キーワードを対象に全カテゴリを検索。検索結果にはカテゴリ名を表示。
- **クイック操作バー**: キーボード有効化、入力方法の切り替え、検索、バックアップへ1タップで移動。ホームでのみ表示。
- **タブバー**: 常時表示。選択中のタブは単色のインジケーターで示す。
- **ホーム**: キーボードの有効・選択状態、端末内処理の状態、よく使う設定、カテゴリのショートカットを表示。
- **戻る操作**: 検索中は検索を閉じ、ホーム以外のタブではホームへ戻る。ホームでの戻るは画面を閉じる。
- **設定の詳細画面**: 既存の入力・変換・辞書・外観などの編集画面はそのまま開く。設定ホームはハブとして、検索とタブで到達性を上げる。

## 検証範囲

- 設定カタログの検索、タブの絞り込み、バックアップの埋め込み除外を単体テストで確認。
- debug／release の lint、APK／AAB のビルドを既存のゲートで確認。
- **実機・エミュレータでの見た目、スクロール、インセット、タブ切替、検索キーボード、Dark mode は未確認**。端末幅、文字サイズ、3ボタン／ジェスチャーナビゲーション、Android 7〜16 での確認が必要。
