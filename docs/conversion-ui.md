# 変換候補UI（rc.30）

rc.29の固定3列・6候補・番号付き表示は廃止した。

## 操作と表示

- 外観設定の「候補の行数」（1行／2行）を、入力中と変換中の両方に反映する。
- 文字は標準20spとし、「候補の文字サイズ」の倍率と端末の文字サイズを反映する。候補番号や件数の専用ヘッダーは表示しない。
- 候補は実際の文字幅と余白を測って並べる。長い候補は幅を広く使い、片手表示や大きな文字では1ページの件数を減らす。幅を超える長文は省略し、一覧で読む。
- 最初の「変換」で先頭候補を選択する。以後は実際に表示中の候補だけを巡回し、末尾から同じページの先頭へ戻る。
- 候補欄の左右スワイプでページを切り替える。別ページの先頭候補が選択される。読み上げのスクロール操作にも対応する。
- 右端の下向きボタンで候補一覧を開く。一覧は番号なし・1列の大きな文字とし、上向きボタンでキーボードに戻る。一覧では候補をタップして選び、変換キーでは進めない。
- 全文AI候補は一覧に「全文」と表示し、文節候補の巡回には混ぜない。
- 通常は文節操作バーを表示しない。一覧の「文節を調整」から開く。同じ場所の「文節操作を閉じる」で隠せる。入力欄では下線・背景で対象文節を示し、カーソルは変換範囲の末尾に維持する。

## 実装と検証範囲

Mozcから最大120件を取得する。全体番号をページ内添字として使わず、候補IDでフォーカスを解決する。ビューが実測幅から決めた表示中IDを変換キーへ渡す。未計測・一覧・ツールメニューなどで表示ページを確定できない場合、変換キーで隠れた候補へ進めない。幅変更時は再計測する。

幅・文字サイズ・行数に応じた収まり、全候補の順序維持、表示中IDだけの巡回、古いID・空ページでの停止、先頭候補、全体番号のID解決を単体テストで確認する。実機・エミュレータでの表示やタッチ操作は未確認である。特に片手・横画面・分割画面、文字サイズ変更、左右スワイプ、一覧復帰、文節操作を確認する必要がある。
