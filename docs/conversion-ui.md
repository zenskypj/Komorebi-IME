# 変換候補UI（rc.31）

rc.29の固定3列・6候補・番号付き表示は廃止した。

## 操作と表示

- 外観設定の「候補の行数」（1行／2行）を、入力中と変換中の両方に反映する。
- 文字は標準20spとし、「候補の文字サイズ」の倍率と端末の文字サイズを反映する。候補番号や件数の専用ヘッダーは表示しない。
- 候補は実際の文字幅と余白を測って並べる。長い候補は幅を広く使い、片手表示や大きな文字では1ページの件数を減らす。幅を超える長文は省略し、一覧で読む。
- 最初の「変換」で先頭候補を選択する。以後は実際に表示中の候補だけを巡回し、末尾から同じページの先頭へ戻る。
- 候補欄の左右スワイプでページを切り替える。別ページの先頭候補が選択される。読み上げのスクロール操作にも対応する。
- 右端の下向きボタンで候補一覧を開く。一覧は番号なし・1列の大きな文字とし、上向きボタンでキーボードに戻る。一覧では候補をタップして選び、変換キーでは進めない。
- 全文AI候補は一覧に「全文」と表示し、文節候補の巡回には混ぜない。
- 通常は文節操作バーを表示しない。一覧の「文節を調整」から開く。同じ場所の「文節操作を閉じる」で隠せる。入力欄では下線・背景で対象文節を示し、カーソルは変換範囲の末尾に維持する。

## 入力中の解析と文節操作

Mozcは従来から `mixed_conversion` と `use_actual_converter_for_realtime_conversion` により、入力更新ごとに実際の変換器で複数文節を解析し、その結果を予測候補に合成する。入力カーソルが末尾にあるときは読み全体が対象で、途中へ動かすと先頭からカーソルまでを対象とする部分予測になる。入力中の表示上の読み区間と、変換後の言語的な文節は同じものではない。rc.31では `use_realtime_conversion` も明示的に有効化する。重いAIの再推論を毎打鍵追加する変更ではない。

入力中に左右キー・長押しカーソルで選んだ先頭側の読みの区切りを記録し、最初の変換で第一文節の読みに引き継ぐ。文節の長さは漢字表示の文字数ではなく、Mozcが返す読みのコードポイント数で合わせる。後ろへの追加入力では維持し、記録した読みの先頭部分自体を編集・削除した場合は古い区切りを破棄する。端で動かなかった左右キーは区切り指定として扱わない。複数の固定境界を入力前に設定する機能ではない。

| 段階 | キーボードの左右キー |
| --- | --- |
| 読みの入力中 | 読み内のカーソル移動・先頭側の予測範囲指定 |
| 最初の変換直後 | 前／次の文節へ移動 |
| もう一度変換し、候補選択に入った後 | 左で文節を縮める、右で広げる |

候補ページをスワイプして選ぶ場合も候補選択段階に入る。候補選択中でも、文節操作バーの「前の文節／次の文節」、文節の直接タップ、スペース長押しのカーソル操作では文節移動を行える。「縮める／広げる」とスペースの横フリックは段階にかかわらず明示的な幅変更である。部分確定後は次の文節の移動段階へ戻る。

Mozcは変換開始・文節幅変更後などに候補ウィンドウを一時的に隠す。この場合も `all_candidate_words` のcategory・focused_indexを見て変換中と判断し、保持中の文節を作り直さない。読みも変換前のキャッシュだけに依存せず、各文節のkeyから取得する。

## 実装と検証範囲

Mozcから最大120件を取得する。全体番号をページ内添字として使わず、候補IDでフォーカスを解決する。ビューが実測幅から決めた表示中IDを変換キーへ渡す。未計測・一覧・ツールメニューなどで表示ページを確定できない場合、変換キーで隠れた候補へ進めない。幅変更時は再計測する。

幅・文字サイズ・行数に応じた収まり、全候補の順序維持、表示中IDだけの巡回、古いID・空ページでの停止、先頭候補、全体番号のID解決を単体テストで確認する。実機・エミュレータでの表示やタッチ操作は未確認である。特に片手・横画面・分割画面、文字サイズ変更、左右スワイプ、一覧復帰、文節操作を確認する必要がある。

rc.31では候補ウィンドウなしの実protobuf形式、第一文節の読み境界の復元、追加入力・編集・動かなかったカーソル、Unicode、幅変更が進まない場合の停止、変換段階の切り替えを追加テストしている。境界調整中の応答なしは通常のセッション復旧へ渡し、古い状態を成功結果として返さない。実端末のMozcでの連続操作と快適性は未確認である。
