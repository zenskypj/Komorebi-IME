# 変換候補UI（rc.32）

rc.29の固定3列・6候補・番号付き表示は廃止した。

## 操作と表示

- 外観設定の「候補の行数」（1行／2行）を、入力中と変換中の両方に反映する。
- 文字は標準20spとし、「候補の文字サイズ」の倍率と端末の文字サイズを反映する。候補番号や件数の専用ヘッダーは表示しない。
- 候補は実際の文字幅と余白を測って並べる。長い候補は幅を広く使い、片手表示や大きな文字では1ページの件数を減らす。幅を超える長文は省略し、一覧で読む。
- 最初の「変換」で先頭候補を選択する。以後は実際に表示中の候補だけを巡回し、末尾から同じページの先頭へ戻る。
- 候補欄の左右スワイプでページを切り替える。別ページの先頭候補が選択される。読み上げのスクロール操作にも対応する。
- 右端の下向きボタンで候補一覧を開く。一覧は番号なし・1列の大きな文字とし、上向きボタンでキーボードに戻る。一覧では候補をタップして選び、変換キーでは進めない。
- 全文AI候補は一覧に「全文」と表示し、文節候補の巡回には混ぜない。
- 通常は文節操作バーを表示しない。一覧の「文節を調整」から開く。同じ場所の「文節操作を閉じる」で隠せる。入力欄では下線・背景で対象文節を示し、カーソルは変換範囲の末尾に維持する。

## 入力中の解析と文節操作

Mozcは従来から `mixed_conversion` と `use_actual_converter_for_realtime_conversion` により、入力更新ごとに実際の変換器で複数文節を解析し、その結果を予測候補に合成する。入力カーソルが末尾にあるときは読み全体が対象で、途中へ動かすと先頭からカーソルまでを対象とする部分予測になる。入力中の表示上の読み区間と、変換後の言語的な文節は同じものではない。rc.31では `use_realtime_conversion` も明示的に有効化する。重いAIの再推論を毎打鍵追加する変更ではない。

入力中に左右キー・長押しカーソルで選んだ先頭側の読みの区切りを記録し、最初の変換で第一文節の読みに引き継ぐ。文節の長さは漢字表示の文字数ではなく、Mozcが返す読みのコードポイント数で合わせる。後ろへの追加入力では維持し、記録した読みの先頭部分自体を編集・削除した場合は古い区切りを破棄する。端で動かなかった左右キーは区切り指定として扱わない。複数の固定境界を入力前に設定する機能ではない。

| 段階 | キーボードの左右キー |
| --- | --- |
| 読みの入力中 | 読み内のカーソル移動・先頭側の予測範囲指定 |
| 最初の文節で変換1回目の直後 | 前／次の文節へ移動 |
| もう一度変換し、候補選択に入った後 | 左で文節を縮める、右で広げる |

最初の変換キーを押した直後、まだ文節移動も候補選択もしていない状態で確定すると、文全体を先頭候補で確定する。変換キーをもう一度押す、文節を移動・タップする、候補を選ぶ、入力を編集する、のいずれかを行うと、従来どおり選択中の文節までを確定して次の文節へ進む。

候補ページをスワイプして選ぶ場合も候補選択段階に入る。候補選択中でも、文節操作バーの「前の文節／次の文節」、文節の直接タップ、スペース長押しのカーソル操作では文節移動を行える。「縮める／広げる」とスペースの横フリックは段階にかかわらず明示的な幅変更である。前の文節を確定して読みが残ったら、次の文節の候補を自動で開いて先頭候補を選ぶ。2文節目以降は変換キーを押し直す必要がなく、候補選択段階から操作できる。すでにネイティブ側が変換中ならその状態を維持し、読みへ戻っていた場合だけ候補を開く。最初の文節の二段階操作は維持する。

Mozcは変換開始・文節幅変更後などに候補ウィンドウを一時的に隠す。この場合も `all_candidate_words` のcategory・focused_indexを見て変換中と判断し、保持中の文節を作り直さない。読みも変換前のキャッシュだけに依存せず、各文節のkeyから取得する。

## 実装と検証範囲

Mozcから最大120件を取得する。全体番号をページ内添字として使わず、候補IDでフォーカスを解決する。ビューが実測幅から決めた表示中IDを変換キーへ渡す。未計測・一覧・ツールメニューなどで表示ページを確定できない場合、変換キーで隠れた候補へ進めない。幅変更時は再計測する。

幅・文字サイズ・行数に応じた収まり、全候補の順序維持、表示中IDだけの巡回、古いID・空ページでの停止、先頭候補、全体番号のID解決を単体テストで確認する。実機・エミュレータでの表示やタッチ操作は未確認である。特に片手・横画面・分割画面、文字サイズ変更、左右スワイプ、一覧復帰、文節操作を確認する必要がある。

rc.31では候補ウィンドウなしの実protobuf形式、第一文節の読み境界の復元、追加入力・編集・動かなかったカーソル、Unicode、幅変更が進まない場合の停止、変換段階の切り替えを追加テストしている。境界調整中の応答なしは通常のセッション復旧へ渡し、古い状態を成功結果として返さない。実端末のMozcでの連続操作と快適性は未確認である。

## rc.32 の操作追加

ツールメニューの「キーボードの高さ」から、入力欄とキーボードを表示したまま調整できる。「保存」で反映、「取消」で元へ戻し、「標準」で100%を試せる。アプリ別プロファイルが有効ならそのアプリの高さ、それ以外は全体の高さを保存する。入力中の変換セッションは作り直さない。

QWERTYスペースの左右フリックを長押しすると連続カーソル移動になる。中心から14dp以内は停止し、離れるほど速くなるが、最短130ms間隔が上限である。処理が遅れてもまとめて進めず、反転時には待ち時間を置く。指を離す・キャンセル・画面を閉じると停止する。通常のかなフリックの長押しは従来のドラッグ式を維持する。長押し中の「カーソル」表示はキー幅と高さに収め、狭ければ2行にする。長押し中のフリックガイドは表示しない。

日本語予測の順位調整は SUGGESTION と PREDICTION の両方、かな・日本語QWERTYに適用する。助詞1文字で終わる候補や助詞から始まる候補でも、実際の読みの対応が確認できれば、文字種だけの候補や誤入力補正より先に並べる。入力より長い別の読みを同じものとみなさない。明示的な優先登録とネイティブ学習履歴も利用する。AI候補の先頭表示・自動選択は利用者の希望により維持する。ただし、ユーザー辞書・ネット辞書へ個別に登録した語や★の優先指定がある読みでは、その語を先頭に保ち、AI候補に押しのけられない。対象は「利用者が個別に指定した内容」に限り、Mozc本来の語彙・予測・訂正やAI生成候補は従来どおり順位付けする。

AI自動学習が有効なときは、確定した読みを結果のkeyから取得し、文脈ありと文脈なしの例を学ぶ。さらに対応が確認できるネイティブ文節や、助詞に挟まれた明確な漢字・カタカナの複合語を再利用する。AI文章を推測で単語分割したり、「泳いで」の「で」を助詞として切り捨てたりしない。文字種を変えただけの読みの反復はTTT再学習から除外する。既存の学習ON/OFF・機密欄の抑止・暗号化保存・リセットを引き継ぎ、新しい学習ファイルは作らない。モデルによる一般的な精度向上や端末上の性能はまだ測定していない。

## rc.42: Mozc非同期化

Mozcを専用の直列ワーカーへ移し、結果をUI側へ戻す試験的実装。文字・削除・変換・文節・確定を受付順に実行します。入力先の終了／切り替え／外部消去では古い未処理イベントと結果を破棄します。キー受付時の配列と機密欄等の設定を保持。2行候補・ツールバーを再利用し、候補欄の二重更新を削減します。

キューの順序・世代・破棄・UI非ブロック性を単体テストで確認します。実機の入力先互換性・連打・速度・FPS・メモリ・ライフサイクルは未確認。詳細は[入力操作](manual/01-nyuryoku.md)と[仕様](manual/09-spec.md)を参照。

## rc.43: 変換1回直後の全文確定

変換キーを1回押して候補が開いた直後、文節移動も候補選択もしていない状態の確定は、選択中の文節ではなく文全体を先頭候補で確定する。長い文を一度で確定したいときの操作を短くするためで、文節ごとの確認をしたい場合は変換キーをもう一度押す、文節を移動・タップする、候補を選ぶ、入力を編集する、のいずれかを行う。これらを行った後は従来どおり、確定で選択中の文節までを確定して次の文節へ進む。

最初の変換で文節が1つしかない場合は従来と同じ結果になる。判定は `WholeSentenceConfirm` に分離し、全文確定の条件と、二回目の変換・未変換のスペースで解除されることを単体テストで確認する。
