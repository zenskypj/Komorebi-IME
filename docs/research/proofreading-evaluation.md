# 小型モデルの校正・量子化比較

2026年11月4日。rc.29では0.8B・1.7Bを優先して調査した。大きいモデルへの自動切り替えは追加していない。

## 条件

合成した日本語21例を [評価文](proofreading-evaluation.json) に保存した。誤字・脱字・助詞・重複・複数文の途中の誤りに加え、正常文、名前の読み、数値、URL、メール、コードを含む。8例を開発用、13例を追加確認用として用意したが、今回の調査中に両方を参照している。独立した未見評価ではない。

アプリが配布する固定リビジョンのGGUFをSHA-256で照合し、ホストのOllamaへ登録した。0.8BのQ4/Q6/Q8はすべて同じモデル・同じリビジョンである。既存インストール済みの別リビジョンのQ8とは比較していない。

`scripts/evaluate_proofreading.py` は実アプリの `ProofreadPrompt`・`ProofreadDiff`・`ProofreadReview` をKotlinでコンパイルして使用する。rawプロンプト、greedy、context 2048、最大出力1024トークンで固定した。元の本文にない思考制御文字列や未完了の生成は失敗扱いとする。記録にはGGUF・指示・後処理のSHA、元の出力、表示用出力を含めた。

これはPC上の比較であり、Androidのllama.cppバックエンドとは異なる。端末の速度・メモリ・発熱は測定していない。完全一致は、この21例で不要な加筆も含めて確認する厳しい回帰指標であり、日本語全般の精度ではない。正しい別表現でも不一致になる。

## 結果

| モデル | ファイル容量（十進MB） | 保護処理後の期待文との完全一致 |
| --- | ---: | ---: |
| Qwen3.5 0.8B Q4_K_M | 532.5 | 12 / 21 |
| Qwen3.5 0.8B Q6_K | 639.0 | 10 / 21 |
| Qwen3.5 0.8B Q8_0 | 811.8 | 11 / 21 |
| Qwen3 1.7B Q4_K_M | 1107.4 | 15 / 21 |

量子化を弱めることで容量は増えたが、この条件では改善を確認できなかった。Q4が一般にQ6/Q8より優れているという意味ではない。今回の結果だけを根拠にQ6/Q8を標準化せず、従来のQ4を維持する。

0.8Bの同じ生成出力を保護処理なしで比較すると8/21、rc.29の保護処理を通すと12/21となった。主に書式やリテラルの不要変更を抑える効果であり、モデルが誤変換を見抜く能力そのものが向上したとは解釈しない。0.8Bでは「資科」を見逃す、または「資材」に誤訂正する例が残る。1.7Bにも文中の見逃しが残る。

短い校正指示も別途比較した。1.7Bでは文中の「資科」を「資料」に直せたが、正常な予定文に「行います」を加えるようになり、全体は15/21で変わらなかった。0.8Bでは11/21に下がったため、指示文の置き換えは採用しなかった。例文を大量に足す、JSON差分を出させる、文ごとに再推論する方式も安定した改善を確認できず採用していない。

## 再現

モデルをローカルのOllamaへrawテンプレートで登録し、JDK 17以上とGradleで取得済みのKotlinコンパイラを用意する。例：

```sh
python3 scripts/evaluate_proofreading.py \
  --model komorebi-proofread-eval-rc29:q4 \
  --gguf /tmp/komorebi-qwen35-08b-q4km.gguf \
  --output /tmp/proofreading-result.json
```

保存済みの出力を再利用するときは `--replay /tmp/proofreading-result.json` を指定できる。モデル・プロンプト・GGUF・評価文の一致を検査し、再推論せず現在の保護処理を適用する。保存した最終結果はこの方式で、符号保護を含む最終版の処理を適用した。

`--baseline-ref v0.3.0-rc.28-dev` で旧指示・保護処理なしも実行できる。入力は同梱の合成文だけで、接続先は `127.0.0.1:11434` 固定である。利用者の文章や実在する人の画像を評価データに含めていない。

最終比較の生出力は [結果ファイル](proofreading-results/) に保存する。モデルの固定リビジョンは [配布候補情報](proofreading-models.json)、追加量子化ファイルは [Unslothの同一リビジョン](https://huggingface.co/unsloth/Qwen3.5-0.8B-GGUF/tree/6ab461498e2023f6e3c1baea90a8f0fe38ab64d0) を参照。raw APIの条件は [Ollama API](https://docs.ollama.com/api/generate)、量子化の説明は [llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/quantize/README.md) を参照。
