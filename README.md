言葉を木漏れ日のようにそっと照らす、Android向けオープンソース日本語IMEです。
入力内容を端末の外へ送らずに使えます。
[Mozc](https://github.com/google/mozc) をネイティブ組み込みし、フリック入力と QWERTY
入力、ユーザー辞書、誤入力補正、キーボードの外観カスタマイズに対応しています。

## 特長

- **入力内容は端末内** — Mozc変換は完全オフラインです。外部サーバーとの通信は任意の
  モデル・辞書取得時だけ。Meets Beamのファイル・辞書転送はNFCとWi-Fi Directの端末間通信で、
  外部サーバーを経由しません。入力内容・周辺文脈は送信しません。
- **Mozc / Karukan切り替え** — 高速・省電力なMozcと、文脈を考慮する実験的な
  Karukanニューラル変換を設定から選べます。Karukanは約32 MBのモデルを明示操作で取得し、
  推論は端末内で行います。
- **端末内のAI文章校正** — 選択した文章、またはカーソル直前の600文字を、任意で取得する
  Qwen3.5 0.8B / Qwen3 1.7B / Gemma 4 E2B モデルで校正します。書き換えの種類
  （誤字・文法／丁寧／簡潔／自然／自由指示）を選べ、結果を元の文章との差分で確認してから
  「適用／適用しない／コピー」を選べます。文章は端末の外へ送信しません。
- **3 種類の入力方式** — かな/英字ともフリック、かな/英字とも QWERTY、かなフリック
  + 英字 QWERTY から選べます。
- **実用的な日本語変換** — Mozc の学習・予測変換に加え、キーと方向の類似度による
  フリックずれ、促音・撥音の脱落、重複入力、隣接文字の転置をルールベースで補正します。
  入力どおりの変換、補正、続きを推測した候補を分けて並べ、明示的に最優先登録した候補は
  読みが一致したとき先頭へ固定します。
- **辞書を端末内で管理** — ユーザー辞書を GUI から追加・編集・削除でき、Mozc /
  Google 日本語入力互換 TSV を端末のファイル選択画面から取り込み・書き出しできます。
  カタカナから英語綴りを引く CC BY-SA 3.0 辞書も同梱できます。候補の意味は、人が
  追加しやすい独立した JSON 意味辞書から参照できます。
- **入力データを暗号化** — ユーザー辞書と変換学習履歴は Android Keystore の鍵を
  使って保存時に暗号化します。クラウドバックアップも無効です。
- **配列と外観を自由に作成** — Material You、ピュアブラック、キーの高さ、生成アート
  背景プリセット、自分の背景画像に
  対応。配列・テーマはプリセットから選択でき、アプリ内で JSON を複製・編集・検証・
  インポート・エクスポートできます。
- **アプリごとに自動切り替え** — 入力方式、片手モード、キーの高さ、シークレット
  モードを、IMEを実際に使用したアプリのパッケージ名ごとに保存できます。
- **設定の検索** — 項目名・説明・関連語でカテゴリをまたいで探せます。[設定画面](docs/manual/13-settings-ui.md)は、カテゴリごとに1つの一覧にまとめています。

名前は、入力を邪魔せず言葉を照らす「木漏れ日」に由来します。ランチャーアイコンは
木漏れ日、葉、キーボード、テキストカーソルを組み合わせた生成アートです。

## インストールと初期設定

Release Candidate のテスト用APKは
[GitHub Releases](https://github.com/zenskypj/Komorebi-IME/releases) から取得できます
（いずれも pre-release・debug 署名版のため、正式版用の署名ではありません）。
自分でビルドする場合は[開発者向けビルド](#開発者向けビルド)を参照してください。

インストール後は次の順に設定します。

1. 「Komorebi IME」を起動する。
2. 「キーボードを有効化」から Komorebi IME を有効にする。
3. 「キーボードを選択」から Komorebi IME を選ぶ。
4. 設定画面の「試し入力」で変換できることを確認する。

初回起動時は同梱の追加辞書をバックグラウンドで取り込みます。進捗は設定画面の
「追加辞書」で確認できます。この処理にもネットワーク接続は使いません。

Karukanを使う場合は「変換エンジン・辞書」から軽量モデルをダウンロードし、完了後に
Karukanを選びます。現在、ニューラル変換の正式対応は `arm64-v8a` です。モデル未導入、
非対応CPU、読み込み失敗時はMozcへ安全にフォールバックします。

application ID がフォーク元と異なるため、Android 上では別アプリとして共存します。
フォーク元や旧 `dev.oss.ime` ビルドの設定・学習履歴・ユーザー辞書は自動移行されません。

## 使える機能

### 入力と変換

- フリックかな、フリック英数、2面のフリック記号
- ローマ字 QWERTY、英字 QWERTY、2 面の QWERTY 記号
- 予測候補の表示と候補タップによる確定
- 候補長押しによる意味表示、最優先候補の登録・解除、削除可能な学習候補の個別削除
- 濁点・半濁点・小書き文字の切り替え
- カーソル移動、Undo、連続 Backspace、変換、確定
- 入力欄側で文字列やカーソルが変更された場合の composition 同期
- パスワード・数値・URL・メール欄に合わせた入力面と候補表示の自動最適化

パスワード欄では Mozc のシークレットモードも自動で有効になり、その入力を学習せず、
既存の学習履歴も変換に利用しません。パスワード欄を離れると通常モードへ戻ります。

composition 同期により、たとえば Chrome のアドレスバーを「×」で消した後に、消す前の
読みが次の入力へ混ざることはありません。
変換エンジンから応答が返らなかった場合も、画面上の未確定文字は通常文字として保持して
内部状態だけを初期化するため、次のキーで古い確定文字が突然現れたり、Backspaceが効かない
状態に固定されたりしません。

URL・メール欄では英字 QWERTY と英語候補を表示します。パスワード・数値欄では候補領域を
非表示にし、特にパスワード欄では学習も行いません。
SSH端末などが非リッチ入力欄（`TYPE_NULL`）を公開している場合、Backspaceは文字列編集API
ではなく物理キー相当のDELイベントとして送り、左右キーもDPADキーイベントとして端末側へ
確実に伝えます。Enterはアプリが送信・検索・完了などの役割を明示していれば、複数行入力欄
でもその操作を優先します。入力欄が明示アクションを受け付けなかった場合だけ、複数行欄では
通常の改行、それも非対応なら物理Enterへ段階的に切り替えます。成功後に別方式を重ねないため、
二重送信はしません。明示アクションのない複数行欄は改行、端末欄は物理Enter相当になります。

候補がないときは同じ領域がMaterialアイコンのツールバーになり、文体補正、
クリップボード履歴からの貼り付け、絵文字、片手モードの切り替え、設定画面への移動を
行えます。片手モードは1つの
ボタンをタップするたびに 全幅 → 左寄せ → 右寄せ → 全幅 と循環し、端末枠内の
キーボード位置を模したインジケーターで現在のモードを表示します。5つのボタンは候補領域の
横幅いっぱいに等分され、端末幅に余白を残しません。
候補が出ると自動的に通常の候補一覧へ戻ります。クリップボード履歴は最大20件で、同じ内容を
重複させず新しい順に表示します。履歴はメモリ内だけに保持され、IMEプロセスの終了または
「すべて消去」で消えます。Android側で機密指定された内容とパスワード欄では収集しません。

絵文字パレットは「最近」「絵文字」「顔文字」「お気に入り」に分かれています。項目を
長押しするとお気に入りへ追加・解除でき、選んだ項目は端末内の最近使った一覧に記録されます。

文体補正は入力中の未確定文字、またはカーソル直前の文章を「堅い敬語」「緩い敬語」
「ノーマル敬語」「ゆるく」「ふつう」へ端末内だけで変換します。「原文」は文章を
書き換えません。外部AIサービスへ文章を送信せず、定型表現の最長一致、活用辞書、
文末・接続節の解析、主語に応じた尊敬語／謙譲語の選択を多段で行うため、オフラインでも
利用できます。辞書にない活用は無理に推測せず、原文を保って不自然な誤変換を避けます。
引用文、URL、メールアドレス、インラインコード、コードブロックは保護し、その周囲だけを
補正します。文章中の識別子や引用内容を壊さないことも精度の一部として扱います。

候補を長押しすると、読みと意味を表示します。意味辞書にない候補も最優先候補へ登録でき、
同じ読みでMozcがその候補を返したときは `★` 付きで先頭へ表示します。4文字以上の読みは
1文字の挿入・削除・置換・隣接転置（8文字以上は2編集）まで類似一致として復元します。
補正候補には「補正」を表示し、入力どおりの候補、補正候補、続きを推測した予測候補の順を
保ちます。入力全文のひらがな・カタカナ・半角カタカナ表記は常に候補内へ残し、自然な
第一候補になった表記を除いて一覧の末尾側へ表示します。学習に由来し削除可能な候補の場合
だけ「学習削除」も表示します。

未変換中にスペースを押すと、Mozcが読みを一般的な日本語IMEと同様に文節へ自動分割して
変換します。変換中はIMEが扱う全範囲を薄いオレンジ、選択文節を濃いオレンジで表示し、
左右の矢印キーで対象文節を移動できます。
スペースキーを左右にフリックすると、選択文節の境界を縮小・拡大できます。

変換エンジンの標準は「自動」です。導入済みのKarukanモデルがあれば、AI変換（zenzai）が無効・利用不可・候補を返さない場合に、入力停止後にKarukan候補を生成します。AIの応答待ちが続く場合も代わりの候補を用意します。文章は自動で確定せず、候補の選択または確定操作で反映します。

「Karukan」を明示的に選ぶとAI有効時にも候補を生成し、変換キーでもKarukanを利用します。「Mozc」はKarukanを使わない設定です。明示変換ではMozcの文節操作と候補も維持します。古い要求の結果は破棄し、モデル未導入・非対応CPU・失敗時にはMozcで入力を継続します。パスワード欄・シークレットモード・アプリ別のAI禁止設定ではKarukanを呼び出しません。

変換前にスペースキーを左右にフリックすると、未変換文字列内のカーソルを1文字ずつ移動
できます。その位置から入力を続けても、既存の未変換文字列は保持されます。変換確定後の
予測候補が表示されているときは、通常どおりエディタのカーソルを移動できます。

### 入力操作の改善（0.3.0-rc.25-dev 開発版）

- スペース長押し後の左右ドラッグでカーソルを移動します。短い左右フリックは従来の操作です。
- 変換中の矢印は文節移動、文節バーは境界変更です。バーの文節を直接タップして選択できます。
- 定型文はメニューから選択して挿入でき、設定から管理できます。
- 設定の「入力の使い方」から、フリック図・文節操作の体験・入力練習を備えた専用ガイドを開けます。

### アプリ別入力プロファイル

設定画面の「アプリ別入力プロファイル」では、アプリごとに入力方式、片手モード、
キーボードの高さ、Mozcのシークレットモードを自動適用できます。

インストール済みアプリを列挙する権限は追加していません。AndroidからIMEへ通知された、
実際に入力したアプリのパッケージ名だけを端末内に記録し、設定候補として表示します。
パッケージ名を手入力して設定を先に作ることもできます。パスワード欄のシークレット設定は
常に優先され、プロファイルで無効化できません。

### 辞書

設定画面の「ユーザー辞書」から、読み・単語・品詞を登録できます。正本は
Mozc / Google 日本語入力の辞書ツールと互換性のある TSV として管理され、端末上では
暗号化して保存されます。

辞書画面上部の「取込」「書出」から Android のファイル選択画面を開けます。取り込みは
現在のユーザー辞書を置き換えます。取り込み前に TSV の形式とサイズを検証し、同じ
読み・単語の重複を整理してから暗号化保存します。

ビルド時に次の追加辞書を同梱できます。

- [google-ime-user-dictionary-ja-en](https://github.com/KEINOS/google-ime-user-dictionary-ja-en) —
  カタカナ語から英語綴りへの変換（例: 「ぶらっく」→ `black`）

元データを結合・検証し、翻訳語を除外して英語綴りを正規化した派生辞書を
[CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/) で再配布します。
出典、ライセンス、変更内容は生成する辞書ファイル自身にもコメントとして埋め込みます。
権利関係が明示的なライセンスだけでは判断できないスクレイピング由来辞書は、標準配布物へ
含めません。
任意取得のNEologdは公式のApache-2.0とCOPYING内の出典表示を確認し、固定コミットの全seedを
個別データセットとして配布します。SKKも辞書ごとの原条件とソースを保持し、ライセンス群を分けます。
[収録方針と再生成手順](docs/extra-dictionaries/README.md)を参照してください。

各データのライセンスと再配布上の注意は [NOTICE](NOTICE) を確認してください。

### 意味辞書

意味辞書はMozcの変換辞書とは分離したJSONファイルです。設定画面から取り込み、ひな形の
書き出し、追加辞書の削除ができます。

```json
{
  "id": "my_dictionary",
  "label": "自分の意味辞書",
  "entries": [
    {
      "term": "木漏れ日",
      "reading": "こもれび",
      "meanings": ["木々の葉の間から差し込む日光。"],
      "tags": ["名詞"],
      "source": "自作"
    }
  ]
}
```

照合は候補の表示文字列と`term`の完全一致です。候補の出所は問わないため、Mozc標準辞書、
同梱追加辞書、ユーザー辞書、学習履歴のどこから出た候補でも、同じ語を意味JSONへ登録すれば
長押しで意味を参照できます。Mozcの語彙データそのものには一般的な国語辞典の意味情報が
含まれないため、未登録語の意味が自動生成されることはありません。

### 外観と配列

設定画面では入力方式、キー操作のバイブ、キーの高さ、ピュアブラック、背景画像と濃さを
変更できます。バイブはテーマに関係なく「入力方式」からオン・オフできます。
背景画像と濃さだけを変更した場合は、表示中の入力ビューを作り直さず、Insets適用済みの
背景パネルをその場で再描画します。設定画面から戻った直後もナビゲーション領域との位置関係
を維持します。端末が通知するナビゲーションバー、必須ジェスチャー、キーボード切替などの
OS操作領域がIMEウィンドウと実際に交差する場合だけセーフエリアとして保持し、背景は連続
させたままキーだけを退避します。Android 7–14でOSが先に確保した領域は二重加算せず、
Android 15–16のedge-to-edgeでは通知された重なりを確保します。
背景画像には「森のともだち」「水晶の藤」「サイバー墨」「月夜のこもれび」の4つの
生成アート・プリセットを同梱し、自分の画像を読み込まなくてもすぐに選択できます。
「プリセット選択・自作・共有」から配列・テーマスタジオを開き、使用するプリセットも
選択できます。キーボードは次に開いたときに設定を反映します。

配列スタジオの「視覚的な配列エディタ」では、キーを選んで行内・行間を移動し、キー幅、
表面ラベル、長押し記号をGUIから変更できます。保存した配列は同じJSON形式のユーザー版に
なるため、JSONエディタやインポート・エクスポートとの互換性も維持されます。

片手モードは全幅・左寄せ・右寄せから選択でき、候補がないときのツールバーの1ボタンを
タップするたびに 全幅 → 左 → 右 → 全幅 と循環して切り替わります。「かなフリック +
英字 QWERTY」では、英字面の左下を常に「かな」切り替えにして、入力方式の切り替え位置を
統一しています。

配列とテーマは JSON です。スタジオでは次の操作ができます。

- 同梱プリセットまたは作成済みデータを選んで使用
- 視覚エディタでキー移動、幅変更、表面ラベルと長押し記号を編集
- JSON の `id` を変更して既存プリセットを複製
- JSON を直接編集し、形式と値を検証して保存
- Android のファイル選択画面から JSON を取り込み・書き出し
- ユーザー版を削除し、同名の同梱プリセットへ復元

作成数にアプリ側の固定上限はありません。同じ ID のユーザー版は同梱版より優先されます。
ID には 1〜64 文字の英数字、ハイフン、アンダースコアを使用できます。安全のため、
1ファイルが 1 MB を超える JSON、空の配列、過大な行・キー数、範囲外のサイズ値などは
保存されません。Material You は端末の配色から動的生成されるため、直接編集・書き出しの
対象外です。

フリック記号は2ページあり、`1/2`・`2/2`キーで切り替えます。2ページ目には括弧、
引用符、比較・演算記号、矢印、プログラミングで使う記号を収録しています。
設定の「フリックの連打」では、同じキーを何度押しても中央文字を入力する「フリックのみ」
と、連打で同じ行の文字を循環する「フリック＋ケータイ打ち」を選べます。ケータイ打ちでは
約0.65秒待つか右方向キーを押すと現在の文字を区切り、同じキーを続けて入力できます。
曲がって戻る指の軌跡も最遠点から判定し、ガイドには各入力文字の選択領域を表示します。
英字QWERTYでは上段の文字キーを長押しすると`1`〜`0`を直接入力できます。
配列JSONの各キーへ`longPress`を追加すれば、任意の直接入力記号を割り当てられます。

## プライバシーとセキュリティ

`AndroidManifest.xml` が要求する権限は、任意取得用の `INTERNET`、Meets Beam・NFC移行用の `NFC`、Wi-Fi Direct 用の `ACCESS_WIFI_STATE` / `CHANGE_WIFI_STATE` / `NEARBY_WIFI_DEVICES`、Android 12 以下に限り Wi-Fi Direct 検出用の `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION` です。位置情報は端末の検出だけに使い、位置の記録・送信はしません。外部通信の宛先は Hugging Face 上の公開モデルと GitHub Releases の追加辞書で、利用者が設定画面で開始した取得に限ります。Meets Beam のファイル・辞書転送は NFC と Wi-Fi Direct の端末間通信だけで、クラウドを経由しません。入力内容、周辺文脈、変換履歴、ユーザー辞書、背景画像は外部へ送信しません。

保存データは次のように扱います。

| データ | 保存方法 |
| --- | --- |
| GUI のユーザー辞書 | AES-GCM + Android Keystore |
| Mozc のユーザー辞書 | Keystore 由来の鍵で暗号化 |
| Mozc の変換学習履歴 | Keystore 由来の鍵で暗号化 |
| 最優先候補の読みと表記 | AES-GCM + Android Keystore |
| クリップボード履歴（最大20件） | メモリ内のみ（IMEプロセス終了時に消去） |
| アプリ別プロファイルと入力先パッケージ名 | アプリ専用領域のJSON |
| 最近使った絵文字・顔文字、お気に入り | アプリ専用SharedPreferences |
| 追加した意味辞書 | アプリ専用領域のJSON |
| Karukanモデル | アプリ専用領域（設定画面から削除可能） |
| Android のクラウドバックアップ | 無効 |

これは Android の端末暗号化を置き換えるものではありません。Keystore の実装や安全性は
端末に依存します。設計、移行処理、検証状況は
[docs/profile-encryption.md](docs/profile-encryption.md) にまとめています。

## 既知の制約

- 視覚的な配列エディタはキー移動、幅、ラベル、長押し記号に対応します。フリック方向や
  特殊アクションなど全項目の編集にはJSONエディタを使用します。
- 意味辞書は候補文字列との完全一致です。活用形から基本形を推測したり、Mozcの辞書から
  未登録の意味を自動生成したりはしません。
- Karukanニューラル変換は実験的機能で、現在は `arm64-v8a` に対応します。
  自動候補は有効な日本語の読みを対象とし、かな編集・文節操作・非対応CPUではMozcを維持します。
- AI文章校正は任意のQwen3.5 0.8B / Qwen3 1.7B / Gemma 4 E2Bモデル（約533 MB / 約1.11 GB /
  約3.11 GB、`arm64-v8a`）の取得が必要で、品質は保証しません。小さいモデルは指示に従わない・
  意味を変える場合があるため、差分を確認してから適用してください。入力先アプリによっては
  対象文章を安全に確認できず、適用できないことがあります（その場合はコピーを利用できます）。
- 公開中のテスト用APKはすべて debug 署名の pre-release です。正式版とは application ID が
  異なります（debug 版は `me.zssu.ime.debug`）。
- 暗号化した Mozc ストレージは 64 MB を超えるファイルを読み込めません。
- Keystore を使う Android 固有の暗号化経路は、実機での継続的な検証が必要です。
- Release Candidate 中は設定形式や内部ファイル形式が変更される可能性があります。

正式版の受け入れ条件と実機マトリクスは
[docs/release-readiness.md](docs/release-readiness.md) にまとめています。

不具合を報告する際は、端末名、Android バージョン、入力した文字、期待した結果、
実際の結果、再現手順を添えてください。入力内容を含むログは公開前に必ず確認してください。

## 開発者向けビルド

### 必要なもの

- Git
- JDK 17–21（JRE のみ、および JDK 25 は不可）
- Python 3.12 以上
- Android SDK Platform 36.1 / Build Tools 36.0.0
- Android NDK r28c
- Rust 1.92 と `cargo-ndk` 4.1
- [Bazelisk](https://github.com/bazelbuild/bazelisk) または Bazel
- `curl`、`unzip`

Android SDK の場所は `ANDROID_HOME` に設定しておきます。

このリポジトリの Android Gradle Plugin 8.13.2 は JDK 25 に対応していません。複数の
Java が入っている環境では、`JAVA_HOME` が JDK 17 または 21 を指すことを確認してください。
Android Studio同梱JBRも使用できます。たとえばLinux版では、Android Studioの`jbr`
ディレクトリを`JAVA_HOME`へ指定してGradleを実行します。

### Linux / WSL が必要な工程

Gradle だけでは Mozc のネイティブエンジンは生成されません。`scripts/build_mozc.sh` は
Linux 用 Bazel ホストツールも実行するため、Linux または WSL2 上で実行してください。
Windows の Android Studio で SDK を導入して `assembleDebug` だけ実行しても、
`libmozc.so` と `mozc.data` は生成されません。

現在の Gradle 構成では、次の必須成果物がない状態で APK をパッケージしようとすると
`:mozc:verifyMozcRuntime` が失敗します。変換不能な APK を成功扱いしないための検査です。

```text
mozc/src/main/assets/mozc.data
mozc/src/main/jniLibs/arm64-v8a/libmozc.so
mozc/src/main/jniLibs/armeabi-v7a/libmozc.so
mozc/src/main/jniLibs/x86/libmozc.so
mozc/src/main/jniLibs/x86_64/libmozc.so
```

### ビルド手順

```bash
git clone <this-repository-url>
cd Zinna-IME-forktest

git clone --depth 1 https://github.com/google/mozc.git third_party/mozc

# Mozc の取得、パッチ適用、4 ABI の libmozc.so、mozc.data、proto の配置
./scripts/build_mozc.sh

# Karukan / llama.cpp の arm64-v8a ライブラリと libc++ の配置
rustup target add aarch64-linux-android
cargo install cargo-ndk --version 4.1.2
./scripts/build_karukan.sh

# Mozc のローマ字テーブルからフリック配列と補正用データを再生成
python3 scripts/gen_flick_layout.py

# QWERTY 配列を再生成
python3 scripts/gen_qwerty_layout.py

# APK に入れる追加辞書を取得
./scripts/fetch_dictionaries.sh

printf 'sdk.dir=%s\n' "$ANDROID_HOME" > local.properties
./gradlew :app:assembleDebug
```

Codex Linux など別のLinux環境へ引き継ぐ場合も、上記を先頭から順に実行します。
`third_party/mozc/`、`mozc/src/main/jniLibs/`、`mozc/src/main/assets/mozc.data` は
Git管理対象外なので、Windows側のcheckoutに存在しなくても異常ではありません。
ビルド後は次のコマンドでAPKへの収録を確認できます。

```bash
unzip -l app/build/outputs/apk/debug/app-debug.apk \
  | grep -E 'libmozc\.so|mozc\.data|libkarukan_android\.so|libc\+\+_shared\.so'
```

4 ABI の `libmozc.so`、1つの `mozc.data`、arm64-v8a の
`libkarukan_android.so` と `libc++_shared.so` が表示されてからAPKを実機へ渡してください。

通常は単一APKを生成します。Play向けRelease AABと、GitHub配布用のABI別APKは別々に
生成してください。AABは配信時に端末のABIへ自動分割されます。

```bash
./gradlew :app:bundleRelease
./gradlew -PenableAbiSplits=true :app:assembleRelease
```

生成物は `app/build/outputs/` 以下に出力されます。実機と接続できる場合は、次でも
インストールできます。

```bash
./gradlew :app:installDebug
```

`build_mozc.sh` が Bazel を 2 回実行するのは意図した動作です。Android 向け
`libmozc.so` と、ホストツールが生成するアーキテクチャ非依存の `mozc.data` は、Mozc
側の制約により同じ Bazel コマンドではビルドできません。

## リポジトリ構成

```text
app/              InputMethodService、キーボード UI、設定画面
mozc/             JNI シム、Kotlin ラッパー、生成 protobuf、ネイティブ成果物
karukan/          Kotlinラッパー、arm64-v8aのKarukanネイティブ成果物
patches/          Mozc に適用する誤入力補正・保存時暗号化・JNI軽量化のパッチ
scripts/          Mozc ビルド、配列生成、追加辞書取得
docs/             設計と検証の詳細
third_party/mozc/ 上流 Mozc の checkout（Git 管理対象外）
third_party/karukan/ 固定リビジョンのKarukan engineとAndroid JNI（Git管理対象）
```

### Mozc との境界

アプリは `MozcJNI` を直接扱わず、`MozcEngine` と `MozcSession` を通してセッションの
ライフサイクルと protobuf の入出力を管理します。上流 checkout へ加える変更は
`patches/` に分離し、`scripts/build_mozc.sh` がビルド前に適用します。

フリック配列の JSON が保持するのは表示上の「かな」ではなく、Mozc のローマ字テーブルへ
渡す ASCII キーです。`scripts/gen_flick_layout.py` は上流の `data/preedit/*.tsv` から
対応を生成・検証し、濁点や小書き文字の規則を迂回しないようにしています。

適用する独自パッチは次の 3 つです。

- `0001-rule-based-typing-correction.patch` — OSS 版 Mozc の補正フックへ軽量な
  ルールベース補正を実装
- `0002-android-keystore-profile-encryption.patch` — Mozc の履歴とユーザー辞書を
  Keystore 由来の鍵で暗号化
- `0003-trim-jni-output.patch` — JNIへ返す候補を上位32件に絞り、順位付けに必要な
  読み・表記・出自属性だけを保持
